# 报价与交付 SOP

> 这份文档是「代码安全体检」服务的作业手册。从客户问诊到结项复测，每一步按它执行，交付质量就不会飘。

---

## 一、售前：先问诊，再报价

报价前必须问清 8 个问题。少问一个，后面就可能返工。

| # | 问题 | 为什么问 |
|---|---|---|
| 1 | 代码总量大概多少行？几个仓库？ | 决定报价档位与工时 |
| 2 | 主要技术栈是什么？（Python / Java / Node / Go / PHP） | 决定规则库侧重与是否需要定制规则 |
| 3 | 有没有大模型或 AI 功能？怎么用的？ | AI 相关风险是差异化能力，要单独评估 |
| 4 | 上线时间点是什么时候？ | 倒排工期；急单可上浮报价 |
| 5 | 最担心的问题是什么？ | 决定报告里优先展示的章节 |
| 6 | 有没有已有的安全要求？（客户审阅、招标、等保） | 决定是否需要英文摘要与合规对照 |
| 7 | 代码能不能出内网？ | 决定是在我们机器上跑还是部署到客户内网 |
| 8 | 之前做过安全检测吗？出过安全事件吗？ | 判断客户认知水平与痛点强度 |

**红线**：只接客户**自有或有明确授权**的系统。授权书没签，不开始任何检测动作。

## 二、报价

| 档位 | 价格 | 触发条件 | 工时 |
|---|---|---|---|
| 体验款 | ¥299 / 次 | 单仓库或单模块，纯自动化报告、不含答疑 | 24 小时内 |
| 标准款 | ¥1,280 / 次 | ≤20 万行，主力款 | 3 个工作日 |
| 专业款 | ¥2,980 / 次 | ≤100 万行，有客户/合规要求 | 5 个工作日 |
| 企业款 | ¥8,800 起 | 规模不限，含人工审计与授权范围内验证 | 按范围评估 |
| 季度订阅 | ¥800–3,000 / 月 | 持续迭代的团队，每月一次扫描 + 随时答疑 | 常驻 |

**定价策略（冷启动版）**

定价不是按你的工时定的，是按**客户的信任度**定的。你现在零案例、零评价，
客户面对的从来不是"3980 贵不贵"，而是"凭什么信你"。
所以顺序是先解决信任，再谈价格——只降价不解决信任，只会越卖越便宜、越卖越没人信。

三条铁律：

1. **不要一上来就免费。** 免费吸引的是白嫖党，不给你交付质量的压力，也不产生任何评价。
   要免费就只免费「范围评估」——看目录结构、指出最可能出问题的模块，但不免费出完整报告。
2. **低价 SKU 砍的是交付物，不是质量。** 299 只给自动化报告、不答疑、不复核；
   客户想听你逐条讲，就得升级到 1280。这样低价单的成本能压在 20 分钟以内，不会拖垮你。
3. **前 3 单可以打 5 折，换两样东西**：案例授权（脱敏后可署名写进作品集）+ 一条真实评价。
   这是买信任最便宜的方式——比降价 80% 有效得多，因为它同时补上了"信任"和"证据"。

**报价话术要点**

- 不要报「扫描服务」，要报「上线前的风险清单」。客户买的不是运行一次工具，是放心上线。
- 从 299 的体验款切入。第一次成交的目标是拿到代码和建立信任，不是赚这一单。
- 报急单时直接说明：加急需要占用周末时间，价格上浮 30%——坦白比绕弯更容易成交。
- 客户砍价时，降范围不降价：把 100 万行拆成「本期扫核心模块，下期扫其余」，价格按模块分。
- 案例攒到 5 个以上、且客户愿意背书时，把标准款从 1280 提到 1980–2980。
  **价格是随信任涨的，不是一次定死的。** 现在报低价是为了拿案例，不是为了长期卖低价。

## 三、授权与边界

必须签署《安全检测授权书》，包含五条：

1. **资产权属**：客户声明对检测目标拥有所有权或已获所有者书面授权；
2. **范围界定**：明确列出允许检测的域名、IP、代码仓库，范围外一律不碰；
3. **时间窗口**：约定检测时段，避开业务高峰；
4. **数据处理**：代码与数据的存储位置、保存期限、到期销毁方式，禁止任何形式的外传与复用；
5. **保密条款**：双向保密，报告仅交付给客户指定联系人。

**执行边界**

- 只对客户自有资产做检测；
- 不做任何未授权的测试，不碰范围外的任何系统；
- 自动化扫描默认只读，不修改、不删除客户数据；
- 需要验证的高危项，先在测试环境验证；生产环境验证必须单独书面确认。

## 四、交付流程

### 1. 获取代码（三选一）

| 方式 | 适用 | 说明 |
|---|---|---|
| 代码压缩包 | 体验款、小项目 | 客户自行排除 `node_modules`、`.git` 历史、二进制产物 |
| Git 只读权限 | 标准版及以上 | 只读 deploy key，扫描完立即撤销 |
| 工具部署到客户内网 | 涉密、金融、医疗 | 代码不出门，我们只拿扫描结果 JSON，负责解读与出报告 |

### 2. 执行扫描

```bash
# 标准扫描，生成 HTML / Markdown / JSON 三份报告
python -m codeaudit scan <代码目录> -o reports --title "某某科技 · 订单系统"

# 只出一份给客户看的精简版（只保留严重与高危）
python -m codeaudit scan <代码目录> -o reports --min-severity high --name 客户名-精简版

# 客户内网部署场景：只输出 JSON，回传后由我们出报告
python -m codeaudit scan <代码目录> -f json -o /tmp/scan

# 接入客户 CI：发现问题返回非零退出码
python -m codeaudit scan . --fail-on high -f json
```

### 3. 人工复核（这一步不能省）

自动化报告直接发出去会掉分。交付前必须做五件事：

1. **剔误报**：逐条看严重与高危项，确认可利用性。测试代码、示例配置里的假密钥要划掉并注明。
2. **补上下文**：告警涉及的接口是否真的对外可达？不可达的要降级说明——诚实比吓人更能建立长期信任。
3. **排序**：按「修复成本 × 风险大小」重排优先级，不要只按严重度堆。
4. **补业务影响**：把技术问题翻译成钱。不要写「存在 SQL 注入」，要写「攻击者可通过订单查询接口读取全表用户数据，包括手机号与地址」。
5. **检查打码**：报告里所有密钥必须已完成打码。外发前再核一遍。

### 4. 交付与答疑

- 交付 3 份文件：HTML 报告（客户阅读）、Markdown 报告（开发贴进文档）、JSON（接入 CI）；
- 附一次 60 分钟线上会，逐条走严重与高危项；
- 会议纪要里记下客户承诺的修复时间点，这是复测的钩子。

### 5. 复测

修复完成后重新扫描，把两次 JSON 做对比：

```bash
python -m codeaudit scan <代码目录> -o reports --name 客户名-复测
```

复测报告里突出「已关闭 N 项 / 仍存在 M 项 / 新增 K 项」。这是客户续费的最强理由。

## 五、定制规则（高毛利增值项）

客户的技术栈会用到通用规则覆盖不到的框架。为它写 3–5 条私有规则，可以单独收 2,000–5,000 元：

```json
{
  "id": "CUS001",
  "title": "XX 框架的权限注解缺失",
  "severity": "high",
  "cwe": "CWE-862",
  "langs": ["java"],
  "pattern": "@RequestMapping[^\\n]{0,120}(?![^\\n]{0,200}@PreAuthorize)",
  "fix": "该接口缺少权限注解，请补充 @PreAuthorize 并核对角色表达式。",
  "tags": ["auth"]
}
```

追加到 `codeaudit/rules.json` 的 `rules` 数组即可，无需改代码。这类定制规则能沉淀成行业规则包，是后续产品的雏形。

## 六、命令速查

```bash
python -m codeaudit demo                     # 用内置样本预览报告效果（谈客户时现场演示）
python -m codeaudit rules                    # 列出全部 60 条规则（给客户看覆盖范围）
python -m codeaudit scan <目录> --title "客户名"   # 正式扫描
python -m codeaudit scan <目录> --fail-on high    # CI 接入
```
